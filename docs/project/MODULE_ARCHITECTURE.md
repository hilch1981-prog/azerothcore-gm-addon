# AzerothAdmin 기능별 모듈 구조

## 목적

기능 하나를 수정할 때 전체 애드온을 다시 읽거나 함께 고치지 않는다. 잘 동작하던 기능의 회귀를 막고 AI 작업의 입력 토큰을 줄이기 위해 기능 경계, 데이터 경계, 테스트 경계를 고정한다.

## 이번 기반 변경의 범위

- 기존 Lua 기능과 파일 위치는 그대로 둔다.
- 공통 모듈 레지스트리와 다국어 레지스트리만 먼저 추가한다.
- `MODULE_MANIFEST.json`에 현재 파일 소유권과 향후 이동 위치를 기록한다.
- 실제 파일 이동과 로직 분리는 기능별 후속 PR에서 하나씩 수행한다.

대규모 일괄 이동은 하지 않는다. 이 원칙은 정상 동작하던 기능이 다른 수정 때문에 깨지는 문제를 줄이기 위한 것이다.

## 최종 모듈 폴더 규격

```text
AzerothAdmin/Modules/<Feature>/
  Module.lua       # 공개 진입점과 의존성
  Service.lua      # 게임/서버 동작
  UI.lua           # 해당 기능 프레임만 소유
  Data.lua         # 작은 수동 데이터만 사용
  Locales/
    enUS.lua
    koKR.lua
    zhCN.lua
    zhTW.lua
```

대용량 생성 데이터는 `Generated/` 또는 기존 데이터 디렉터리에 두고, UI/로직 수정 시 기본 컨텍스트에서 제외한다.

## 기능별 작업 규칙

1. `MODULE_MANIFEST.json`에서 대상 기능을 찾는다.
2. `shared_context`와 해당 모듈의 `runtime_files`, `tests`만 먼저 읽는다.
3. 데이터 변경이 없으면 `data_files`와 `ignore_by_default` 파일을 읽지 않는다.
4. 한 브랜치와 PR에서는 한 기능만 이동하거나 수정한다.
5. 다른 기능 파일을 수정해야 하면 공개 인터페이스가 부족한 이유를 먼저 기록한다.
6. UI 문자열은 코드에 직접 넣지 않고 해당 모듈의 locale pack에 등록한다.
7. enUS를 기본값으로 하고 koKR, zhCN, zhTW 키가 동일한지 CI에서 검사한다.
8. 게임 내 테스트 전에는 완료로 표현하지 않는다.

## 권장 이동 순서

1. 은행
2. 부활
3. 퀘스트 도우미
4. 크리처 브라우저
5. 아이템 정보
6. 전문기술 정보
7. 순간이동
8. 검색/대용량 데이터
9. 공통 UI와 명령 셸

각 단계는 별도 `codex/<기능명>` 브랜치와 별도 PR로 진행한다.

## 언어 선택

- 클라이언트 로케일이 `enUS`, `koKR`, `zhCN`, `zhTW`이면 해당 언어팩을 자동 선택한다.
- `/aalang enUS`, `/aalang koKR`, `/aalang zhCN`, `/aalang zhTW`로 클라이언트 로케일과 다른 언어를 선택할 수 있다.
- `/aalang auto`는 수동 설정을 해제하고 클라이언트 로케일로 되돌린다.
- 언어 변경은 SavedVariables에 저장하고 UI 재시작 후 적용한다.
- 아직 legacy 기능 파일에 직접 들어 있는 한국어 문자열은 각 기능을 모듈로 옮기는 후속 PR에서 함께 분리한다.
